Purpose

Provides rootless XWayland integration for Wayland compositors that don't have built-in XWayland support (primarily niri). Translates X11 window management requests into Wayland protocol calls, enabling legacy X11 applications to run on pure Wayland compositors.

Networking Crates
ZERO. No reqwest, hyper, tokio-net, curl, ureq, or any HTTP library in Cargo.toml.

Network Activity

CONFIRMED ZERO external network calls. All IPC via Unix domain sockets only.

Complete I/O inventory:
  • Local Wayland socket (compositor communication)
  • Local X11 socket (Xwayland communication)
  • Unix socket pairs (internal fd passing)
  • /proc/{pid}/environ read (for XDG_ACTIVATION_TOKEN)
  • sd_notify (local systemd socket for readiness notification)

No TCP/IP, no UDP, no HTTP, no DNS lookups. Entirely local Unix socket IPC.

Process Execution

Only spawns Xwayland. This is the expected and documented behavior — the entire purpose of the program is to manage an Xwayland instance.

  • Spawns: Xwayland binary (the X11 server for Wayland)
  • No other process spawning
  • No shell invocation

Build System

  • build.rs: Only calls vergen_gitcl to embed version info at compile time. No downloads, no URL fetches.
  • Standard Cargo build with no custom build scripts that access the network

Unsafe Code Analysis

Limited unsafe usage, all in standard fd-based IPC patterns:

  • OwnedFd::from_raw_fd() — converting raw file descriptors to owned types
  • BorrowedFd::borrow_raw() — borrowing file descriptors for IPC
These are standard Rust patterns for Unix socket/fd-based IPC. No memory-unsafe operations, no pointer arithmetic, no FFI abuse.

Privilege Requirements

Runs entirely in userspace. No privilege escalation, no setuid, no capabilities required. Communicates with the Wayland compositor and Xwayland via Unix domain sockets only.
