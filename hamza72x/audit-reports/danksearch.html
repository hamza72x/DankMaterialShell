Role
Optional dependency — provides file search for the DMS Spotlight launcher

Purpose

A local file indexing and full-text search daemon. Walks configured directories, indexes file names/metadata/content using Bleve (full-text search engine), and serves results via a localhost-only HTTP API and Unix domain socket. Used by the DMS launcher to provide fast file search.

Network Activity

ZERO outbound network calls.

  • HTTP server binds to 127.0.0.1:43654 (localhost only) — inbound/local only
  • Unix socket server at $XDG_RUNTIME_DIR/danksearch-<pid>.sock — local IPC only
  • No http.Get, http.Post, http.Client, or http.NewRequest for outbound traffic
  • No curl, wget, or external HTTP calls in the Go code
  • The /docs page loads a CDN script in the browser (not fetched by the binary)

All indexed data remains on local disk. Nothing is ever sent externally.

File Access

Indexes
User-configured directories (default: $HOME, max depth 6). Hidden directories excluded by default (exclude_hidden = true), so .ssh, .gnupg, .env are NOT indexed.
Stores
~/.cache/danksearch/index (Bleve index) and meta.db (BoltDB metadata)
Text content reading
Limited to configured extensions (.go, .py, .js, .md, etc.) with max 2MB per file

Process Execution

Zero exec.Command usage. No arbitrary code execution. No process spawning of any kind.

Security Concerns

  • None critical.
  • HTTP API has no authentication — but binds localhost-only, so only local processes can access it.
  • If exclude_hidden is manually set to false, sensitive dotfiles would be indexed — but data remains local and this requires explicit user opt-in.
  • Bleve metrics explicitly disabled: "metrics": false

Verdict

SAFE

After inspecting every source file: zero outbound network calls, zero exec.Command usage, zero telemetry, zero obfuscated code. All indexed data stays on local disk, served only to localhost. A clean, well-structured local file search tool with no malicious behavior.
