Purpose

A Material You / Material Design 3 color scheme generator. Reads a wallpaper image, extracts dominant colors using the Material Design color algorithm, and writes rendered template files (config files for GTK, terminals, editors, etc.) to user-specified paths. This is the theming engine that powers DMS's dynamic wallpaper-based color schemes.

Network Activity

Default build: ZERO network calls.

Optional features (NOT compiled by default):
  • web-image feature: Uses reqwest to download an image from a user-specified URL. Download-only (GET), no data sent. Requires explicit --features web-image at build time.
  • update-informer feature: Checks crates.io for newer versions. Only sends package name + version. Requires explicit opt-in in config (version_check = true).

Neither feature is in the default feature set. DMS uses the default build.

Process Execution

The program spawns shell commands in two user-configured scenarios:

  • Template hooks (pre_hook / post_hook): Defined by the user in their own config file. Runs after generating colors to apply them (e.g., reload a window manager).
  • Wallpaper command (config.wallpaper.command): User-configured command to set the wallpaper (e.g., swww img {{image}}).

No hardcoded commands are executed without user configuration. This is a standard pattern for "rice" tools (pywal, wpgtk, etc.).

File Access

Reads
  • Image file (user-specified via CLI)
  • Config file (TOML, from XDG config dir or --config flag)
  • Template input files (user-specified in config)
  • Cache files from $XDG_CACHE_HOME/matugen/images/
Writes
  • Template output files at user-specified output_path (creates parent dirs, respects permissions)
  • Cache files at $XDG_CACHE_HOME/matugen/images/ (JSON with computed color schemes)

No writes to sensitive system locations. All output paths are user-configured.

Security Concerns

  • None critical.
  • The execute crate runs commands through the system shell. If a user's config were tampered with by another program, hooks could run malicious code. Same trust model as any dotfile-based tool.
  • Template output paths are user-controlled, so a misconfigured template could overwrite unintended files. The program checks for read-only permissions before writing.

Verdict

SAFE

The default build makes zero network connections. All shell command execution is explicitly user-configured (hooks and wallpaper commands). File I/O is limited to user-specified template inputs/outputs and a standard XDG cache directory. No telemetry, analytics, data collection, or exfiltration. No build.rs. No obfuscated code. The project is GPL-2.0 licensed with 1.8k stars and packaged in official Linux distribution repos.
