Purpose

A QML-based shell framework built on Qt 6 that renders the entire DMS user interface. Provides the runtime environment for QML components including windows, layer-shell surfaces, system tray integration, and Wayland protocol support. Designed as a shell toolkit — QML configurations can spawn subprocesses by design.

Network Activity

ZERO external network calls at runtime. All "network" code is local DBus/Unix socket IPC.

Detailed analysis of network-related code:
  • The Socket class uses QLocalSocket (Unix domain sockets) exclusively — NOT TCP/IP
  • The src/network/ module is a NetworkManager DBus client (local system bus only) — reads connection status, does not make network connections
  • Only URL in codebase: crash reporter GitHub issue URL — never fetched programmatically, only opens in user's browser on explicit click

No telemetry. Zero analytics. Zero phone-home.

Process Execution

QML configurations can spawn subprocesses — this is by design as Quickshell is a shell toolkit. This is analogous to how a shell (bash/zsh) spawns commands. The user's QML config controls what gets spawned.

Risk assessment: Process spawning is expected behavior for a desktop shell framework. The framework itself does not spawn any unexpected processes — all subprocess spawning is user-directed via QML configuration files.

Security Concerns

  • None critical.
  • cpptrace vendored dependency is pinned to v1.0.4 (good: reproducible builds, no supply chain drift)
  • Process spawning is inherent to the shell toolkit design — equivalent to any shell executing commands
  • No obfuscated code, no hidden functionality
